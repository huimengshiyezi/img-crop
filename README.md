# 图片裁剪（img-crop）

把**一批图片**按同一个裁剪框裁好 —— 或者**每张单独裁**。拖一次框，整队一起裁；处理完自动打包成一个 ZIP 下载。

> **纯本地处理 · 文件不上传 · 断网可用** —— 所有运算都在你自己的浏览器里完成，图片不会离开这台设备。

## 它一共五项能力

| # | 能力 | 说明 |
|---|---|---|
| 1 | **共享队列** | 点击选择 / 拖拽 / **Ctrl + V 粘贴** 多张图；缩略图列表显示张数与单张处理结果、单张移除；可清空；**一张一张按顺序处理**（解一张用完即释放），带进度与「正在处理第 N / 共 M 张」，**可取消**，单张失败只标红不中断 |
| 2 | **裁剪（主角）** | **可以直接拖的裁剪框**：拖框内 = 移动，拖 8 个手柄 = 缩放；比例锁在预设上（原图比例 / 1:1 / 3:4 / 4:3 / 16:9 / 9:16 / 21:9 / 自定义宽高），框内有三等分参考线、框外变暗，带「居中 / 重置 / 覆盖全部」；**支持触屏拖动** |
| 3 | **两种裁剪粒度** | 默认**整队统一**：拖一次框，全队每张都按同样的相对位置裁，最省事；打开**「每张图单独裁剪」**后，每张图各记一个裁剪框，切图时各自恢复，适合逐张精修 |
| 4 | **四周裁边模式** | 不想拖框时，直接「四周各裁掉 N 像素（或 N%）」，适合去掉截图边框、水印边角、扫描件黑边 |
| 5 | **输出与导出** | 目标格式 保持原格式 / JPG / PNG / WebP；JPG 与 WebP 的画质滑块（40~100）；输出文件名后缀可改（默认 `_crop`）；一键打包 ZIP，或只下载当前这一张；批量结束显示张数 / 成功失败 / 总体积变化 |

## 三步上手

1. **选图片**：把图拖到第一个框里（或点一下选择，或直接 `Ctrl + V` 粘贴截图）。
2. **拖裁剪框**：右边（手机上在下面）会出现图片和裁剪框 —— 拖框内移动、拖 8 个小方块缩放；先在上面选个固定比例（比如 `1 : 1`）。
   想每张单独裁，就打开 **「每张图单独裁剪」**，然后逐张点缩略图分别拖。
3. **导出**：有需要就改一下目标格式或后缀，然后点 **「一键处理全部 → 打包下载 ZIP」**。想先试一张就用「只下载当前这张」。

## 尺寸口径只有一种

界面上显示的数字**一律是「真实导出分辨率」**：`原图 3376 × 1440 ｜ 裁剪后导出 1440 × 1440 像素（占原图 43%）`。

编辑器里那张图是按比例缩小显示的（大图缩到长边 1000 像素以内，不然又慢又吃内存），
但那只是**显示**用的，**不会**出现在任何数字里 —— 你看到的就是导出后文件的真实像素尺寸。

> 为什么专门写这一条：如果拿显示用的缩小画布去算裁剪范围，同一份裁剪框在大图上和小图上会解出两套不同的矩形，
> 就会出现"界面说裁了 600×600、导出却是 450×450"这类对不上的问题。这个工具从设计上就只认原图那一套。

## 裁剪会不会让画质变差？

**裁剪本身是像素级搬运、不重采样** —— 它只是把要的那块像素原样抠出来，不会像"缩小图片"那样重新插值，
所以裁剪这一步不会让画面变糊。

剩下就看**目标格式**：

| 情况 | 结果 |
|---|---|
| 保持原格式 | PNG 源不变差；JPG / WebP 源要用同格式重新存一次，画质基本不动 |
| 目标 **PNG** | **不新增损失**（PNG 是无损容器）。但如果原图本来是 JPG / WebP，它在当初被压缩那一刻就已经掉过画质了 —— 转成 PNG 只是"不再新增"，**救不回**已丢的细节 |
| 目标 **JPG / WebP** | 这是有损格式，**必然再掉一次画质**（由画质滑块决定），而且救不回原图已经丢掉的细节 |

界面上会按你当前选的格式，把上面这几句如实写出来。

## 处理顺序与内存

一次处理一张，**解一张、裁一张、编码一张、用完立刻释放**，所以几百张也不会把内存吃满。
进度条下面会写「正在处理第 N / 共 M 张」。中途想停就点「取消」。

## 已知限制（如实说明）

- 支持 **JPG / PNG / WebP** 三种输入。**iPhone 的 HEIC 格式浏览器读不了** —— 界面上会直接告诉你「先在手机「照片」里导出成 JPG」。这也是浏览器本身的限制，不是工具的问题。
- 打包用的是最朴素的 store 模式 ZIP（不压缩），所以 ZIP 体积约等于所有输出图的体积之和；单条目超过 4 GB 或条目数超过 65535 需要 ZIP64，本工具不支持（图片场景到不了）。
- 输出总量超过约 1.2 GB 时不会打包，而是**给出具体的分批建议**（例如「这批共 42 张、合计 3.8 GB……建议分 4 批处理（每批约 11 张）」）。
- 没有撤销功能：处理是不可逆的，**建议先拿一两张试参数，确认了再整批跑**。原图不会被改动。
- 参数与「每张单独」开关会记在本机浏览器里（`localStorage`，只存设置、不存图片），下次打开自动恢复；底部的 **「恢复默认」** 可以一键清掉。

## 浏览器要求

Chrome / Edge / Firefox / Safari 的较新版本都可以。需要浏览器支持 `createImageBitmap` 或 `Image` 解码、
以及 `canvas.toBlob`。手机上（≤560px 宽）也能用，裁剪框可以用手指拖。

## 隐私

- 没有任何外部请求：不开 CDN、不加载字体、不上报数据。
- 图片**只在你自己的浏览器内存里**处理，不会上传到任何服务器。
- 唯一的本地写入是 `localStorage` 里那点设置（开关、比例、后缀之类），可以随时用「恢复默认」清掉。

<summary>给开发者：这个工具的代码是怎么来的 / 怎么改</summary>

`index.html` 是**构建产物**，不要直接手改（改完下次构建就没了）。源码在仓库外的 `..\3-开发脚本\`：

| 文件 | 作用 |
|---|---|
| `extract.mjs` | 从 `img-batch` 的产物里**逐字节**抽出纯计算区（索引区）/ ZIP 引擎 / 一些工具函数 |
| `_app.js` | 本工具自己的应用层源码（队列、编辑器、导出、记住设置） |
| `_shell.html` | 页面骨架：CSS + DOM + 拼接用的占位符 |
| `build.mjs` | 把上面几样拼成 `0-repo\index.html`，并做一堆自检（导出/定义对账、必需函数齐全） |
| `selfcheck.mjs` | 静态检查 + 把纯计算区抽进 Node 的 `vm` 里**真跑**几何断言 |
| `smoke.mjs` | 假 DOM 里把整页跑起来，端到端验队列 / 裁剪 / 导出 / ZIP / 每张单独裁剪 |
| `verify-zip.py` | 用 Python 标准库 `zipfile` 独立复核 JS 产出的 ZIP（手撕本地头对账） |
| `mutate.mjs` | 变异测试：故意改坏源文件再重建，确认上面三个脚本**真的会报错** |

```bash
cd ..\3-开发脚本
node extract.mjs    # img-batch → _parts\（img-batch 改了才需要重跑）
node build.mjs      # → 0-repo\index.html
node selfcheck.mjs && node smoke.mjs && python verify-zip.py
node mutate.mjs     # 断言有效性自证（13 个变异，全部应被咬住）
```

**为什么要"先抽再拼"而不是手抄**：裁剪几何（比例锁定、最小尺寸地板、归一化往返）在原工具里
已经被两千多组断言钉过，手抄一遍必然抄出错。这里靠 `extract.mjs` 逐字节搬运，
再用 `build.mjs` 里的对账断言保证"搬过来的东西没多也没少"。

几何代码在产物里位于 `PURE-CORE-START/END` 标记之间 —— 自检就是靠这对标记把它整段
抽出来丢进 `vm` 里跑的。
